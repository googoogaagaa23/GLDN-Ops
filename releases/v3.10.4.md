# GLDN Ops v3.10.4

## Scope

- Repair Move .99 final-page verification that could remain on page 2 after all filtered rows were captured.
- Recover automatically when an unpacked-extension update invalidates an already-open eBay tab.
- Reduce cross-computer races and eBay interruption risk without changing approval boundaries.
- Remove dashboard credentials from public release packages.

## Move .99 Repairs

- The workflow now derives the logical last page from eBay's filtered `Results` total. For example, `201-232 of 232` ends on page 2 even when another eBay control still exposes an account-wide page count.
- Popup and internal launchers delegate to one background transaction that creates a blank tab, stamps and binds the workflow to that exact tab, then navigates it to eBay.
- An invalidated old content script stops its timers and refreshes the eBay tab once. It no longer leaves dead controls displaying `Ready`.
- eBay bot, captcha, and interruption pages stop the workflow before any listing change. Page navigation uses a slower randomized delay.
- The final review is locked to the exact Chrome tab and eBay workspace. A trusted operator click is recorded, but GLDN Ops never clicks Submit.
- If Submit or the review page disappears without both that trusted click and an explicit eBay result, the run stops as `approval-lost`. It cannot navigate, create another workspace, or start another batch.

## Packaging and Dashboard

- Public packages are credential-free and cannot contain the dashboard setup code.
- Dashboard setup is stored in each Chrome profile and survives runtime-file updates.
- Existing ignored local configuration can migrate once; a new Chrome profile uses `Setup > Connect Dashboard` once.

## Safety

- Exact item IDs and exact `.99` prices remain required.
- No listing is submitted automatically.
- Every eBay Submit remains a separate action-time approval stop.
- A detected eBay interruption stops safely instead of retrying through the challenge.
