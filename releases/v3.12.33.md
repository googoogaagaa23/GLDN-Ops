# GLDN Ops v3.12.33 - Policy Audit Recovery

## Changes

- Completes policy classification from saved final-page scans instead of requesting an extra eBay page.
- Processes 100 listings per batch with visible classification counts and pause support.
- Recovers interrupted scan workers and preserves saved pages after a failed results save.
- Keeps read-only policy checkpoints across updates; old marketplace End approvals are not reused.
- Hides the unused End-review section and keeps the audit read-only.
- Builds on v3.12.32 without changing policy rules, installation pairing or other workflows.

## On M0

Use GLDN Ops **Update & Reload** and verify **v3.12.33**. Reopen **Existing Listings Policy Audit** and choose **Resume Scan**, not Start Fresh or Discard. The existing checkpoint is revalidated before results are produced.

If the old version refuses to update because the frozen audit is still marked active, do not use Reset: that removes its recovery state. Run the current **GLDN Ops Setup** against the same existing loaded folder, then reload GLDN Ops from Chrome's Extensions page (or restart Chrome). Keep the same extension/profile; do not uninstall it or clear extension storage. A different loaded folder may require updating that folder explicitly.

## Verification

The repair has executable coverage for an 18,359-listing checkpoint, missing/duplicate rows, classification pause, failed storage commit, identity/rule mismatches, upgrade preservation and progress rendering. A synthetic full-size run using the actual 580-rule pack emitted 185 progress updates with a maximum 182 ms between updates. Classification comparison fixtures preserve the previous decisions and fingerprint.

Signed-in completion and CSV readback on M0 remain unverified because that computer is not connected here. This release makes the repair available at the user's request; local, package and fixture verification are not a live eBay pass. No listings were changed during preparation.
