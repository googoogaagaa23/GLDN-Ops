# GLDN Ops v3.11.1

## Scope

- Repair the local updater handshake discovered during the signed-in Profile 2 v3.11.0 launch.
- Preserve the exact Chrome-loaded-folder targeting and marketplace approval boundaries introduced in v3.11.0.
- Make a stale Poshmark workflow checkpoint visible and recoverable from the Poshmark panel itself.

## Updater Repair

- Chrome extension service-worker requests can omit the HTTP `Origin` header even when the request is legitimate.
- GLDN Ops now sends its exact runtime extension ID in a dedicated updater header.
- The updater accepts the no-Origin shape only when Chrome reports `Sec-Fetch-Site: none`, `Sec-Fetch-Mode: cors`, and a valid extension ID.
- The extension ID is resolved against Chrome's unpacked Profile data before any folder can be read or changed.
- Ordinary website origins, mismatched IDs, unknown IDs, and ambiguous loaded folders remain rejected.

## Interface Recovery

- The Poshmark panel now includes Stop Task and Reset controls.
- Reset requires a visible confirmation and clears only saved GLDN workflow state; it does not change marketplace data.
- Health output labels approval-ready checkpoints as awaiting review instead of describing them as actively running.

## Verification

- The updater fixture covers both the real no-Origin service-worker request and rejection of an ordinary website origin.
- The full JavaScript suite, local install/update/rollback fixtures, generated-guide drift check, package inspection, and release gate must pass before publication.
- Signed-in Chrome Profile 2 / computer `0` / FAK12 remains the only accepted live browser for this launch.
- No marketplace Continue, Save, Submit, purchase, or equivalent final action is authorized by this release note.
