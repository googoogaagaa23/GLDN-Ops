# GLDN Ops v3.12.59

Date: 2026-10-19

## Orders Left Response Timeouts

The count now acknowledges startup immediately, then checks source account identity without scanning the entire visible order list. Startup failures are retained as a clearly partial run with Stop/Recount recovery instead of failing before state exists.

Native snapshots index order-link ancestry once and reuse row/header/text/visibility evidence within that one read. The caches are discarded after each snapshot so saving a note remains detectable. The packaged reader is reused and repaired only if absent.

Browser responses have a thirty-second allowance rather than ten seconds. If a response stalls, the same outstanding operation is awaited instead of queuing repeated scripts into the same tab. Partial reads remain stable until the operator chooses Recount; they do not launch a new failed run every few seconds.

The counter remains read-only, follows every current-filter native page, counts unique orders without any saved note and excludes canceled/cancelled orders. Account, filter, exact order, saved reader and normal/incognito checks remain enforced. Nothing is purchased, shipped, canceled or edited.
